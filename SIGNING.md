# Постоянный сертификат подписи — один раз настроить

## Зачем это нужно

Если каждый релиз подписывать новым случайным сертификатом, Windows
не разрешает обновлять приложение поверх старого: установщику приходится
удалять старую версию, а вместе с ней слетают настройки и свои пресеты.

С **постоянным** сертификатом все версии подписаны одинаково, и обновления
ставятся как у обычных программ — поверх, с сохранением всего.

Настраивается один раз, занимает ~5 минут. Приватный ключ при этом
**не покидает ваш компьютер** — кроме секрета GitHub, который вы вставляете сами.

## Шаг 1. Создать сертификат у себя на компьютере

Откройте папку с проектом (или скачайте из репозитория файл
`tools/New-TimerSigningCert.ps1`) и выполните в PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\New-TimerSigningCert.ps1
```

Скрипт:

- создаст сертификат `CN=TimerAppDev` на 10 лет (или найдёт уже созданный);
- попросит придумать пароль к нему — **запомните его**;
- положит на рабочий стол в папку `TimerAppCert` три файла;
- сам откроет страницу секретов репозитория в браузере.

## Шаг 2. Создать два секрета на GitHub

На открывшейся странице **Settings → Secrets and variables → Actions** нажмите **New repository secret** два раза:

| Name | Secret (значение) |
|---|---|
| `TIMERAPP_CERT_PFX_BASE64` | Открыть `TimerApp.pfx.base64.txt` с рабочего стола, скопировать **весь** текст и вставить |
| `TIMERAPP_CERT_PASSWORD` | Тот же пароль, что вы ввели в скрипте на шаге 1 |

## Шаг 3. Убрать лишнее и сохранить ключ

- Удалите `TimerApp.pfx.base64.txt` с рабочего стола (он уже в GitHub).
- Файл **`TimerApp.pfx` сохраните в надёжное место** (например, в ваш
  менеджер паролей как вложение). Это «паспорт» приложения: потеряете его —
  следующие версии снова не смогут обновляться поверх старых.
- `TimerApp.cer` можно оставить рядом, он публичный и не секретный.

## Что дальше

Ничего. Со следующего релиза сборка на GitHub сама подхватит сертификат
из секретов (в логе сборки будет «Используется постоянный сертификат подписи
из Secrets»).

**Один нюанс:** самая первая версия, подписанная постоянным сертификатом,
поверх вашей текущей всё равно не встанет — текущая подписана случайным.
Установщик, как и раньше, один раз переустановит приложение начисто
(настройки один раз сбросятся), а вот **все последующие** обновления уже
будут сохранять настройки и пресеты.

## Если секреты не заданы

Сборка продолжит работать по-старому: сгенерирует одноразовый сертификат.
Ничего не ломается, просто обновления между такими релизами ставят
приложение начисто.
